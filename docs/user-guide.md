# User guide

## The 30-second workflow

1. Open any source file.
2. Watch the status bar: `$(sparkle) ~1.2k` is the live token estimate for
   the file (or just your current selection).
3. Run **`CodeSheaf: Copy Active File + Import Dependencies`** from the
   Command Palette (or right-click → CodeSheaf).
4. Paste into Claude / ChatGPT / Gemini / Cursor chat. Done — path headers,
   code fences, a file tree, and a token line are already included.

## Commands

| Command                                             | What it does                                                                                                                                               |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CodeSheaf: Copy Active File as Context`            | Weaves the active file (+ imports per your configured depth) into the clipboard.                                                                           |
| `CodeSheaf: Copy Active File + Import Dependencies` | Same, but guarantees the import closure is followed to depth ≥ 3, regardless of the `0` setting.                                                           |
| `CodeSheaf: Copy Selection as Context`              | Weaves only the selected lines (1-based inclusive range) — imports are still scanned from the full file, so a deep selection still pulls its dependencies. |
| `CodeSheaf: Preview Context Bundle (Active File)`   | Opens the exact bundle text in a read-only editor instead of the clipboard — inspect before you paste.                                                     |
| `CodeSheaf: Copy as LLM Context`                    | Right-click one or more files/folders in the Explorer. Folders expand into files (ignore-pruned, capped at 1000 files).                                    |

The Editor context menu shows _Copy Selection as Context_ when text is
selected, and _Copy Active File_ always; the Explorer context menu shows
_Copy as LLM Context_.

## Output formats

Configured by `codesheaf.format`:

**Markdown** (default) — best for chat UIs:

````markdown
# CodeSheaf Context Bundle

> 3 file(s) · ~412 estimated tokens · generated by CodeSheaf v1.0.0

## Project Tree

```text
project/
├── src/
│   ├── core/
│   │   └── bundle.ts
│   └── a.ts
└── README.md
```

## src/a.ts

```ts
import { Bundle } from './core/bundle';
export const a = new Bundle();
```
````

**XML** — structured, easy to post-process; content lives in CDATA sections
(safe against `]]>` collisions), attributes are escaped.

**Plain** — maximum compatibility: `FILE: path (language)` headers between
separator lines.

## How file picking works

- **Explicitly picked files bypass ignore rules** — if you right-click it,
  you get it (like an `@`-mention in a prompt).
- **Import-discovered and directory-expanded files respect ignore rules**:
  workspace `.gitignore` files plus the `codesheaf.exclude` globs (last rule
  wins, so your exclude list can override gitignore).
- Files that cannot be woven are reported with a precise reason instead of
  failing the bundle: `ignored`, `binary`, `too-large`, `not-found`,
  `unreadable`, `empty-selection`, `depth-limit`, `limit-reached`.

## Import following

Depth is controlled by `codesheaf.maxImportDepth` (default 3, `0` disables).
Only **local** dependencies are followed:

| Language                | Followed                                                                                           | Skipped                                           |
| ----------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| TypeScript / JavaScript | `./`, `../` imports, re-exports, `require()`, dynamic `import()`                                   | bare packages (`react`), URLs                     |
| Python                  | `from .x import`, `from ..pkg import`, absolute `import pkg.mod` (matched against workspace files) | stdlib/third-party that never matches a real file |
| Java                    | `import com.x.Y;` → `com/x/Y.java`, static imports → declaring class                               | wildcards `com.x.*`                               |
| Go                      | block + single imports; relative specifiers                                                        | stdlib names that match no file                   |
| C/C++                   | quoted `#include "..."`                                                                            | system `<...>` includes                           |

## Settings

| Setting                        | Default              | Meaning                             |
| ------------------------------ | -------------------- | ----------------------------------- |
| `codesheaf.format`             | `markdown`           | `markdown` · `xml` · `plain`        |
| `codesheaf.includeLineNumbers` | `false`              | Prefix lines with `N                | ` markers. |
| `codesheaf.includeTree`        | `true`               | File tree at the top of the bundle. |
| `codesheaf.maxImportDepth`     | `3`                  | 0–10; 0 disables import following.  |
| `codesheaf.maxFileSizeKB`      | `256`                | Files above this size are skipped.  |
| `codesheaf.respectGitignore`   | `true`               | Honor workspace `.gitignore` files. |
| `codesheaf.exclude`            | build/lockfile globs | Extra gitignore-syntax patterns.    |
| `codesheaf.statusBar.enabled`  | `true`               | Live token meter in the status bar. |

## Known limitations

- Token counts are heuristic estimates (4 ASCII chars ≈ 1 token; CJK ≈ 1
  token/char), not exact tokenizer output — see [ADR-0004](adr/0004-estimate-tokens-with-a-heuristic.md).
- Import scanning is regex-based and comment/string-aware but not a full
  parser — exotic syntax can be missed; see [ADR-0003](adr/0003-heuristic-regex-import-scanning.md).
- Very large directory picks are capped at 1000 files per directory input.
